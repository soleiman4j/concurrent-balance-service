# Concurrent Balance Service

یک پیاده‌سازی حداقلی برای چالش برنامه‌نویسی [**Concurrent Balance Service**](<docs/Coding%20Challenge%20V2.pdf>).

سرویس مدیریت موجودی حساب‌های بانکی به‌صورت هم‌زمان با استفاده از **Java 21** و **Spring Boot**.

این پروژه پیاده‌سازی ساده‌ای از چالش `Concurrent Balance Service` است. هدف اصلی آن مدیریت عملیات مالی و حفظ صحت موجودی حساب‌ها در شرایط اجرای هم‌زمان درخواست‌ها است.

## قابلیت‌ها

- ایجاد حساب بانکی با موجودی اولیه
- افزایش موجودی (`Credit`)
- کاهش موجودی (`Debit`)
- انتقال وجه بین دو حساب (`Transfer`)
- دریافت موجودی حساب (`Get Balance`)
- جلوگیری از اجرای تکراری تراکنش‌ها با استفاده از شناسه یکتا
- مدیریت هم‌زمانی و جلوگیری از Race Condition
- جلوگیری از انتقال ناقص در صورت بروز خطای عددی
- جلوگیری از Deadlock با ترتیب‌دهی قفل حساب‌ها

## تکنولوژی‌ها

- Java 21
- Spring Boot 3.5.16
- Maven
- JUnit 5
- ConcurrentHashMap

- Virtual Threads

## تصمیمات فنی

### مدیریت هم‌زمانی

برای ذخیره حساب‌ها و تراکنش‌ها از `ConcurrentHashMap` استفاده شده است.

هر حساب دارای یک `ReentrantLock` مستقل است تا عملیات روی یک حساب به‌صورت ایمن انجام شوند و عملیات حساب‌های مستقل بتوانند هم‌زمان اجرا شوند.

در عملیات انتقال وجه، قفل حساب‌ها بر اساس شناسه حساب و با ترتیب ثابت گرفته می‌شود تا احتمال وقوع Deadlock کاهش یابد.

### Idempotency

هر تراکنش دارای یک شناسه یکتا (`transactionId`) است.

- اجرای مجدد تراکنش با همان شناسه و همان پارامترها، عملیات را دوباره اجرا نمی‌کند.
- استفاده از شناسه یکسان برای درخواست متفاوت، با خطای `TRANSACTION_ID_CONFLICT` مواجه می‌شود.
- نتیجه و خطای تراکنش اجراشده برای درخواست‌های تکراری حفظ می‌شود.

### مدیریت خطاهای عددی

برای جلوگیری از سرریز عددی از `Math.addExact` استفاده شده است.

در انتقال وجه، موجودی مقصد پیش از تغییر موجودی مبدأ محاسبه و اعتبارسنجی می‌شود. بنابراین در صورت بروز سرریز، هیچ‌کدام از موجودی‌ها تغییر نمی‌کنند.
